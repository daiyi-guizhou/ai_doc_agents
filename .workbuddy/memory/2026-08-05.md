## 三大增强（用户追加需求）
在原有体系上新增三块能力，均已落地并验证：

### 1. 向量语义去重 `tools/dedup.py`（无依赖默认 tfidf）
- `iter_md` 跳过隐藏目录；`chunk_text` 剥离 frontmatter/代码块/wikilink；`tokenize` 加入中文**bigram**（CJK）提升词汇相似度。
- 三种后端：`tfidf`（标准库，离线默认）、`st`（sentence-transformers，默认 `BAAI/bge-small-zh-v1.5`，真语义）、`api`（env `EMBED_API_URL`/`EMBED_API_KEY`）。
- `--threshold` 省略时按后端自动取默认：tfidf→0.55，st/api→0.80（cosine 比较，>= 阈值报疑似重复对）。
- 限制：tfidf 为词汇级，同义改写（零字符重叠）只能到 ~0.17，需 `--backend st` 才能抓语义改写。

### 2. AI 自动起草 + 巡检
- `tools/draft.py`：按 type→目录映射生成文档骨架（adr/rfc 自动取下一序号），写 frontmatter（status:draft，review_cycle 365d/90d），并在目录 README 注册 `[[link|title]]`。
  - 用法：`python tools/draft.py --type adr --title "..." [--owner X] [--date Y-M-D] [--root docs]`
- `tools/inspect.py`：汇总 doclint(--json) + dedup + 孤儿文档检测，输出 `docs/.reports/inspection-YYYYMMDD.md`。`--threshold` 同样按后端自适应（修复了原先写死 0.8 导致 tfidf 永远不报重复的问题）。
- 自动化 `每周文档库巡检`（id `automation-1785938687580`，rrule 每周一 09:00，ACTIVE）：跑 inspect 并总结 error/warning、疑似重复对、孤儿文档给 owner。
